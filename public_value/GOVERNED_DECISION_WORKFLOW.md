# Governed Farm Decision Workflow

CropCircuit's value layer is most useful when it sits **upstream** of ordinary farm math.

The workflow is:

```text
purpose
→ hard constraints
→ evidence / unknowns
→ right-relationship gate
→ financial + labor + technical analysis
→ reversible experiment where practical
→ measure actual outcome
→ review decision
```

## 1. State the purpose

Do not start with the tool or machine.

Start with the real need.

Examples:

- reduce repetitive livestock chores;
- protect worker time during market season;
- lower water-system failure risk;
- reduce missed maintenance;
- improve margin without increasing stocking pressure.

A clear purpose prevents the optimizer from substituting a different goal simply because it is easier to measure.

## 2. Declare real hard constraints

Only mark a boundary "hard" if the farm actually intends not to trade it away.

Examples:

- legal / safety;
- animal welfare;
- soil / water;
- human capacity;
- critical resilience.

The Right Relationship Gate is deliberately non-compensatory.

A failed hard boundary is not averaged against a strong ROI.

## 3. Separate evidence from assumptions

For each important claim, identify whether it is:

- measured;
- quoted / sourced;
- estimated;
- assumed;
- unknown.

Unknown is not the same as favorable.

## 4. Run the Right Relationship Gate

Use:

- [Right Relationship Decision Gate](right_relationship_gate.html)
- [Gate documentation](RIGHT_RELATIONSHIP_GATE.md)

Possible results:

### REJECT
A required hard constraint fails.

Stop unless the option is redesigned.

### HOLD
No hard boundary is known to fail, but a required boundary or important effect remains unknown.

Gather evidence or reduce the decision to a reversible experiment.

### PASS TO REVIEW
No declared hard constraint fails or remains unresolved.

This does **not** mean "buy it" or "do it."

It means the option can move into ordinary viability and tradeoff analysis.

## 5. Then use ordinary farm math

After an option passes the gate, use the relevant tool:

- repeated labor cost → Farm Math / Labor Opportunity Analyzer;
- equipment threshold → Equipment Cost Threshold Analyzer;
- recurring workload → Chore Load Planner;
- market economics → Farmers Market Break-Even;
- CSA economics → CSA Share Price & Break-Even;
- before / after measurement → Workflow Experiment Analyzer.

The sequence matters:

**values determine the acceptable option set; math compares options inside that set.**

## 6. Check enoughness

Before maximizing further, ask:

- What threshold would solve the stated problem?
- Has that threshold already been reached?
- Is additional output worth the added dependence, complexity, maintenance, or ecological pressure?

This prevents "optimization" from silently turning into endless expansion.

## 7. Prefer reversible experiments

When uncertainty remains and a small test is possible:

- pilot one paddock;
- automate one repeated task;
- test one market day;
- trial one scheduling change;
- run one season before scaling.

A reversible experiment preserves future options and creates better evidence.

## 8. Measure the actual result

Use the Workflow Experiment Analyzer or another transparent before/after record.

Do not assume the intervention achieved the modeled savings.

## 9. Preserve the decision record

For consequential decisions, save a [High-Impact Decision Record](HIGH_IMPACT_DECISION_RECORD.md).

The record preserves:

- purpose;
- boundaries;
- evidence;
- unknowns;
- enoughness;
- reversibility;
- gate;
- outcome;
- review trigger.

That lets later operators and agents understand why the decision was made without inventing a rationale after the fact.
